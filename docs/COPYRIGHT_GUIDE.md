# 软件著作权登记材料指南

本文档说明如何用本仓库准备中国计算机软件著作权登记（软著）材料。

## 1. 建议的软件名称与版本

```text
全称：面料显微图像双模型智能识别软件
简称：面料双模型识别软件
版本：V1.0.0
```

名称、版本应与申请表、源程序页眉、说明书封面保持一致。

## 2. 通常需要的材料

以中国版权保护中心最新要求为准，常见材料：

1. 软件著作权登记申请表
2. 申请人身份证明（企业营业执照/个人身份证）
3. 源程序（一般 60 页）
4. 软件说明书（通常 30~60 页，含功能、操作、界面截图）
5. 代理委托书（如委托代理机构）

官方登记通常不收取登记费，代理服务费另计；具体以最新政策为准。

## 3. 源程序格式

常见要求：

- 每页 50 行；
- 总页数超过 60 页时，提交前 30 页和后 30 页；
- 不足 60 页时提交全部；
- 页眉写软件名称和版本；
- 代码连续，不插入大段无关内容；
- 不要包含密钥、密码、个人邮箱、客户数据。

本仓库提供导出工具：

```bash
python tools/export_copyright_source.py
```

输出：

```text
copyright/source_full.txt       全部源码
copyright/source_60pages.txt    按 50 行/页截取
copyright/README.txt            行数、页数、文件清单
```

工具会：

- 收集 `src/`、`scripts/`、`tests/`、`tools/` 和树莓派推理脚本；
- 去掉行尾空格和连续空行；
- 按 50 行分页；
- 超过 60 页时自动取前 30 页 + 后 30 页。

导出后建议用 Word 打开，设置页眉、页码、等宽字体（宋体/Consolas 10~11pt）。

## 4. 软件说明书建议结构

1. 封面：软件名称、版本、申请人、日期
2. 软件概述：用途、适用场景
3. 运行环境：硬件、操作系统、依赖
4. 安装与启动
5. 界面说明（配截图）
6. 功能操作：摄像头、单图、批量
7. 输出说明：字段、颜色、结论含义
8. 参数配置：阈值、线程、输入尺寸
9. 异常处理与常见问题
10. 技术特点：双模型、级联门控、交叉校验、抗旋转训练

可直接使用：

```text
docs/USER_MANUAL.md
docs/SOFTWARE_DESIGN.md
docs/ALGORITHM.md
```

## 5. 需要补充的截图

至少准备：

1. 主界面空闲
2. “通过”结果
3. “复核”结果
4. 模型自检终端
5. CSV 台账
6. 安装/启动命令

截图要求清晰、无水印、不要出现客户隐私和密钥。

## 6. 算法材料

软著不强制提交算法论文，但算法说明能帮助审查员理解软件独创性。建议提交：

- `docs/ALGORITHM.md`：预处理、门控、档位、交叉校验、指标
- `docs/TRAINING_AND_DEPLOYMENT.md`：训练与试错记录
- `docs/TEST_REPORT.md`：测试结果

不要把第三方模型说成完全自研。可以表述为：

```text
本软件自主实现双模型级联、阈值决策、交叉校验、台账归档和边缘部署流程；
底层分类网络采用开源模型并在自有数据上微调。
```

## 7. 代码权属与许可证

登记前必须确认：

1. YOLOv8 的 AGPL-3.0 商用授权（见 `THIRD_PARTY.md`）；
2. 数据集和拍摄图片的授权；
3. 员工/外包开发成果的权属；
4. 是否使用了他人的预训练权重。

## 8. 提交前检查清单

- [ ] 软件名称、版本在申请表/代码/说明书一致
- [ ] 源程序 60 页，页眉正确
- [ ] 说明书含截图和操作步骤
- [ ] 删除密钥、Token、个人路径、客户数据
- [ ] 第三方许可证已审查
- [ ] 数据集授权文件已归档
- [ ] 保留一份与提交版本一致的 Git 提交号
- [ ] 保存导出时的源码压缩包和校验值

## 9. 版本留档建议

每次提交软著或交付客户时记录：

```text
Git 提交号
模型 SHA256
阈值配置
测试报告日期
```

本仓库对应提交可在 `git log` 查看，模型哈希在 `models/manifest.json`。
